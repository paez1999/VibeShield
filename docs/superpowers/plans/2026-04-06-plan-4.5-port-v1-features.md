- [ ] **Step 2: Update GitHubCodeRepository**

Read the current file, then refactor. The key changes:

1. Replace `fetchFileContent(repo, sha)` (fetches one blob) with `fetchFiles(repo, sha, opts)` (downloads tarball, returns all matching files at once)
2. Keep the existing interface methods (`resolveRef`, `fetchTree`) but add a new method `fetchFiles` that combines tree + content in one tarball download
3. The `CodeRepository` port interface needs updating too — add `fetchFiles`

Update the `CodeRepository` port at `src/domain/ports/codeRepository.ts`:
```typescript
export interface FileEntry {
  path: string
  sha: string
  size: number
  type: 'blob' | 'tree'
}

export interface FileContent {
  path: string
  content: string
}

export interface FetchFilesOpts {
  skip: RegExp
  relevant: RegExp
  maxFiles: number
  maxFileSize: number
}

export interface CodeRepository {
  resolveRef(repo: string, ref: string): Promise<string | null>
  fetchTree(repo: string, sha: string): Promise<FileEntry[]>
  fetchFileContent(repo: string, sha: string): Promise<string>
  fetchFiles(repo: string, sha: string, opts: FetchFilesOpts): Promise<FileContent[]>
}
```

Implement `fetchFiles` in the adapter:
- Download tarball from `https://api.github.com/repos/{owner}/{repo}/tarball/{sha}` (1 API call)
- Write to temp file, parse with `tar.list()` file-based API (tar v7 Minipass streams need this approach)
- Filter entries by `opts.skip`, `opts.relevant`, `opts.maxFileSize`, `opts.maxFiles`
- Strip the top-level directory from paths (GitHub tarballs wrap in `owner-repo-sha/`)
- Return `FileContent[]` with path and content
- Clean up temp file in `finally` block
- If tarball fetch fails, fall back to the existing tree + blob approach

Also keep `fetchFileContent` working (for backwards compatibility with existing tests and the public scan route).

Create a `deduplicateFindings` function (can live in semgrepScanner.ts or a shared util):
```typescript
export function deduplicateFindings(regexFindings: CodeFinding[], semgrepFindings: CodeFinding[]): CodeFinding[] {
  // If Semgrep and regex both report the same location+category, keep Semgrep (more precise)
  const semgrepKeys = new Set(semgrepFindings.map(f => `${f.location}|${f.category}`))
  const filtered = regexFindings.filter(f => !semgrepKeys.has(`${f.location}|${f.category}`))
  return [...semgrepFindings, ...filtered]
}
```
